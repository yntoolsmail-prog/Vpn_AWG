# Vpn_AWG — AmneziaWG + Telegram Bot
AmneziaWG нативно в kernelspace (300+ мбит) с управлением через Telegram бота и терминальное меню.

## Особенности

- **AWG нативно** — модуль ядра, не userspace/Go, полная скорость
- **Обфускация** — не детектируется РКН/DPI
- **Telegram бот** — полное управление сервером прямо из чата
- **Многопользовательский** — каждый пользователь работает в своём пространстве имён, устройства изолированы. Администратор одобряет доступ и видит всех
- **Исключения сайтов** — раздельное туннелирование: выбор из 29 сервисов (банки, госуслуги, маркетплейсы, видео и др.) прямо в боте при создании профиля, также режим ручного исключения сайтов
- **Мониторинг трафика** — текущая скорость, пики, месячное потребление через vnstat
- **Терминальное меню** — полное управление через `vpn.sh` без бота, открывается автоматически при SSH-подключении
- **Автозапуск** — AWG и бот стартуют при перезагрузке сервера
- **Гибкий адрес подключения** — IP сервера или домен/DDNS на выбор; при смене IP достаточно обновить DNS, конфиги у клиентов остаются рабочими

## Требования

- Ubuntu 22.04 или 24.04
- VPS с root доступом
- Telegram бот (получить у @BotFather)

## Установка

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/yntoolsmail-prog/Vpn_AWG/Test/setup.sh)
```

Установщик автоматически:
1. Проверит и при необходимости обновит ядро
2. Установит AmneziaWG (нативный модуль ядра)
3. Сгенерирует случайные параметры обфускации
4. Настроит сетевой интерфейс и IP-форвардинг
5. Установит vnstat и mtr для мониторинга и диагностики сети
6. Установит Telegram бота и настроит автозапуск
7. Настроит автозапуск панели управления при SSH-подключении

## Управление через Telegram бот

Напишите `/start` вашему боту.

### Для всех пользователей

- **➕ Добавить устройство** — создать VPN-профиль. После создания выбрать канал подключения (основной, резервный, по IP) и режим трафика: весь через VPN или с исключениями сайтов
- **📋 Мои устройства** — список устройств с трафиком и временем последнего хендшейка. В карточке: скачать `.conf`, QR-код, поделиться ссылкой для AmneziaVPN, настроить исключения сайтов, удалить
- **📊 Статус сервера** — uptime, load average, RAM, диск, количество клиентов и онлайн, реальный статус AWG-интерфейса
- **📖 Инструкция** — встроенная справка, включая раздел про настройку DNS на клиентских устройствах

### Только для администратора

- **🌍 Все клиенты** — список всех устройств всех пользователей с трафиком
- **👥 Пользователи** — одобрение/отклонение запросов на доступ, удаление пользователей со всеми устройствами
- **📈 Трафик / пики** — текущая скорость, пик за сегодня, абсолютный пик, топ-5 нагруженных минут, месячное потребление за последние 6 месяцев
- **🧹 Очистить мусор** — удалить висячие пиры из AWG которых нет в конфиге
- **💾 Бэкап** — архив конфигов, ключей и данных пользователей
- **📥 Восстановить из бэкапа** — перенос на новый сервер
- **🔧 Техобслуживание** — обновление системы, смена IP, смена часового пояса (список или ручной ввод), проверка версии библиотеки, напоминание раз в 6 месяцев

### Регистрация пользователей

Новый пользователь пишет `/start`, вводит имя латиницей — администратор получает уведомление с кнопками одобрить/отклонить. После одобрения пользователь самостоятельно добавляет устройства. Устройства каждого пользователя изолированы — он видит только свои.

## Управление через терминал (vpn.sh)

При SSH-подключении панель открывается автоматически. Нажмите Enter без выбора пункта чтобы выйти в терминал.

```bash
bash /root/vpn.sh
```

- Удалить клиента — удаляет пир из AWG и все файлы клиента

- Статус сервера — AWG, бот, uptime, RAM, диск, load average, `awg show`

- Настройки — смена токена бота, Admin ID, обновление IP (авто), смена основного и резервного endpoint, смена DNS, просмотр `server.env`
- Бэкапы — создать, список с размерами и датами, удаление по возрасту
- Обновление — `bot.py` + `vpn.sh` из репозитория, `apt upgrade`, `python-telegram-bot`

</details>

- Анализ конфигов — сравнение параметров обфускации, ключей, endpoint и DNS клиентов с сервером. Расхождения помечаются ⚠️
- Предыдущие диагностики — список сохранённых отчётов с датами

</details>

## IP или домен — что выбрать для адреса подключения

<details>
<summary>Читать подробнее</summary>

Когда вы создаёте VPN-профиль для устройства, в него прописывается адрес сервера — через него клиент знает куда подключаться. Этот адрес может быть либо IP-адресом сервера, либо доменным именем.

**IP-адрес** — проще всего, ничего дополнительно настраивать не нужно. Минус один: если вы когда-нибудь смените сервер или хостер изменит IP — все конфиги у всех пользователей перестанут работать и придётся раздавать новые.

**Домен** — чуть сложнее в настройке, зато при смене IP достаточно обновить одну DNS-запись у регистратора домена. Конфиги у пользователей продолжают работать без каких-либо изменений с их стороны.

**Бесплатный вариант через DDNS** — если своего домена нет, можно воспользоваться бесплатными сервисами вроде [DuckDNS](https://www.duckdns.org) или [No-IP](https://www.noip.com). Они дают вам адрес вида `yourname.duckdns.org` — этого достаточно.

**Резервный адрес** — можно задать второй адрес подключения (второй домен или IP). Тогда у каждого клиента будет два профиля: основной и резервный. Если основной не работает — переключаетесь на резервный за секунду.

<details>
<summary><sub>Как настроить домен и резервный адрес</sub></summary>

**Через установщик** — во время установки `setup.sh` спросит домен и проверит что он резолвится в IP сервера.

**После установки:**
```bash
sed -i "s|^SERVER_ENDPOINT=.*|SERVER_ENDPOINT=your-domain.duckdns.org|" /etc/amnezia/amneziawg/server.env
sed -i "s|^SERVER_ENDPOINT_BACKUP=.*|SERVER_ENDPOINT_BACKUP=backup.example.com|" /etc/amnezia/amneziawg/server.env
systemctl restart awg-bot
```

> Новые значения применяются к новым конфигам. Существующим устройствам — зайти в карточку устройства и скачать `.conf` заново.

Или через терминальное меню: `bash /root/vpn.sh` → Настройки → Изменить endpoint.

</details>

</details>

<details>
<summary><sub>DNS на клиентских устройствах — почему это важно</sub></summary>

Если VPN вдруг перестал подключаться после того как всё работало — скорее всего сменился IP-адрес сервера, а ваш роутер или провайдер ещё не узнал об этом.

Когда меняется IP в настройках домена, это изменение расходится по интернету постепенно. На мобильном интернете — **2–5 минут**. На Wi-Fi через некоторых провайдеров — **до 3–4 часов**, потому что роутер кэширует старый адрес и игнорирует настройки DNS даже если вы выставили `1.1.1.1`. Это не проблема только VPN — так работает интернет в целом.

**Решение** — поставить быстрый DNS прямо на устройство (не на роутер):

| Устройство | Где настроить |
|---|---|
| Android | Настройки → Подключения → Другие настройки → Частный DNS → `one.one.one.one` |
| iPhone / iPad | Настройки → Wi-Fi → (i) → Настроить DNS → Вручную → `1.1.1.1`, `1.0.0.1` |
| Windows | Панель управления → Сетевые адаптеры → IPv4 → DNS вручную: `1.1.1.1`, `1.0.0.1` |
| macOS | Системные настройки → Сеть → Wi-Fi → Дополнительно → DNS → `1.1.1.1`, `1.0.0.1` |

После этого изменения IP-адресов будут доходить за **2–5 минут** вместо нескольких часов.

</details>

---

<details>
<summary><sub>Смена DNS</sub></summary>

DNS-серверы прописываются в конфиги клиентов при их создании. Хранятся в `server.env`.

Проще всего сменить через терминальное меню: `bash /root/vpn.sh` → Настройки → Сменить DNS.

Или вручную:
```bash
sed -i 's/PRIMARY_DNS=.*/PRIMARY_DNS=8.8.8.8/' /etc/amnezia/amneziawg/server.env
sed -i 's/SECONDARY_DNS=.*/SECONDARY_DNS=8.8.4.4/' /etc/amnezia/amneziawg/server.env
systemctl restart awg-bot
```

> Новый DNS применяется только к новым устройствам. Существующим — пересоздать профиль.

</details>

<details>
<summary><sub>Обновление</sub></summary>

**Проще всего** — через Telegram бота: `🔧 Техобслуживание` → `💾 Бэкап + apt upgrade`. Там же можно обновить python-telegram-bot и проверить версии.

**Из терминала:**
```bash
bash /root/vpn.sh  # → Обновление
```

**Вручную (из ветки `main`):**
```bash
curl -s https://raw.githubusercontent.com/yntoolsmail-prog/Vpn_AWG/main/bot.py -o /root/bot.py
curl -s https://raw.githubusercontent.com/yntoolsmail-prog/Vpn_AWG/main/vpn.sh -o /root/vpn.sh
chmod +x /root/vpn.sh && systemctl restart awg-bot

apt-get update && apt-get upgrade -y && systemctl restart awg-bot
```

Конфиги, ключи и данные клиентов не затрагиваются.

</details>

<details>
<summary><sub>Для владельца репозитория — amnezia.gpg.asc</sub></summary>

В репозитории хранится GPG-ключ PPA Amnezia. Установщик берёт его оттуда — это позволяет установке работать даже на серверах где заблокирован `keyserver.ubuntu.com`. Пользователям этот файл не нужен.

Если ключ истечёт: скачать актуальный с [keyserver.ubuntu.com](https://keyserver.ubuntu.com/pks/lookup?op=get&search=0x57290828), сохранить как `amnezia.gpg.asc`, загрузить в репозиторий.

</details>

## Защита SSH

SSH-порт сервера открыт в интернет — автоматические сканеры начинают перебирать пароли через минуты после установки.

### fail2ban

Блокирует IP после 5 неверных попыток за 10 минут. Устанавливается через меню vpn.sh (пункт 10 → 5) или напрямую:

```bash
bash /root/setup.sh --ssh
```

### SSH-ключ администратора

При установке система автоматически генерирует единый ключ `/root/.ssh/awg_admin_key`. Этот же ключ бот использует для подключения к slave-серверам. Скачайте его на каждое устройство — и пароль для SSH вам больше не нужен.

**Получить команды для скачивания** — vpn.sh → пункт 10 → пункт 1, или через бота: Техобслуживание → SSH-доступ → Скачать ключ.

**Linux / macOS / Termux:**
```bash
scp -P 22 root@IP_СЕРВЕРА:/root/.ssh/awg_admin_key ~/.ssh/awg_admin_key
chmod 600 ~/.ssh/awg_admin_key
ssh -i ~/.ssh/awg_admin_key root@IP_СЕРВЕРА
```

**Windows (PowerShell):**
```powershell
scp -P 22 root@IP_СЕРВЕРА:/root/.ssh/awg_admin_key "$env:USERPROFILE\.ssh\awg_admin_key"
icacls "$env:USERPROFILE\.ssh\awg_admin_key" /inheritance:r /grant "${env:USERNAME}:(F)"
ssh -i "$env:USERPROFILE\.ssh\awg_admin_key" root@IP_СЕРВЕРА
```

После того как убедились что вход по ключу работает — отключите пароль (vpn.sh → пункт 10 → пункт 4). Это распространится на primary и все slave-серверы автоматически.

### Свои ключи устройств (альтернатива)

Если предпочитаете держать отдельный ключ на каждом устройстве — используйте мастер:

```bash
# vpn.sh → пункт 10 → пункт 2, или напрямую:
bash /root/setup.sh --ssh
```

Мастер поможет сгенерировать ключ на устройстве, скопировать публичный ключ на сервер и проверить вход перед отключением пароля.
