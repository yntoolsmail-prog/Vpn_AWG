# Каскад: российский вход → зарубежные выходы

`cascade.sh` — этап 2 плана переезда: каскад вручную, без бота. Бот на этапе 3
будет вызывать те же подкоманды по SSH.

## Зачем

ТСПУ режет не протокол, а адрес назначения: зарубежные хостинги замораживают
целыми подсетями (поток проходит первые ~10–25 пакетов и затихает — «подключено,
интернета нет»). На российские адреса эта заморозка не действует. Поэтому телефон
подключается к российскому серверу (вход), а тот уводит зарубежный трафик
туннелем на зарубежный сервер (выход). Российские адреса вход выпускает сам —
банки и госуслуги видят российский IP.

## Устройство

```
телефон ──AWG──▶ ВХОД (awg0, копия основного) ──┬─ российские сети: напрямую
                                                ├─ awgx1 ──AWG──▶ выход 1 ─▶ интернет
                                                └─ awgx2 ──AWG──▶ выход 2 ─▶ интернет
```

- **Вход** — обычный слейв (добавлен в боте, `awg0` — копия основного: ключ
  сервера, порт, обфускация, все устройства). Каскад добавляет к нему туннели
  `awgxK`, маршрутизацию и службу `awg-cascade`.
- **Выход** — зарубежный сервер с интерфейсом `awgx0`. Обычно тоже слейв: его
  `awg0` и прямые конфиги продолжают работать. Ключей пользователей на `awgx0`
  нет — только ключи входов, и выход видит только адрес входа (NAT на входе).
- **Номер выхода K (слот)** общий для всех входов и не меняется при замене
  сервера: забанили выход — новый сервер поднимается с тем же `--slot K`.

### Куда идёт устройство

Решает адрес устройства в конфиге (A.B.C — `VPN_SUBNET`, N — номер устройства):

| Адрес | Куда |
|---|---|
| `A.B.C.N` | «Авто»: все нынешние конфиги. Устройства делятся между выходами «Авто» поровну (N mod число выходов) и закреплены за своим — внешний IP не прыгает. Упал его выход — на живой, ожил — обратно |
| `A.B.(C+K).N` | Слот K: выход K. Упал — как «Авто». Выход убран с входа (`entry-del` без `--forget`) — тоже «Авто» |

Адреса слотов служба сама выдаёт каждому устройству на `awg0` входа (только на
интерфейсе, не в `awg0.conf`): бот при синхронизации пира их сбрасывает, служба
возвращает в течение одного интервала. Менять код бота для этого не нужно.

### Решение о маршруте

Принимается на первом пакете соединения и запоминается в нём (метка
соединения, биты 16–23): живые соединения не перескакивают между выходами.

1. Частные адреса — как обычно.
2. Российские сети (`cascade_ru`) и не в `force_exit.list` — напрямую.
3. Слот K, выход K жив — в него.
4. Корзина «Авто» устройства — в её выход, если жив, иначе на живой.
5. Все выходы мертвы — напрямую с IP входа (`CASCADE_ALL_DOWN=drop` — без интернета).

Выход живой, если отвечает его адрес внутри туннеля (`NET.K.1`). Одного
хендшейка мало: заморозка пропускает хендшейк и режет данные. «Упал» — после
3 неудач подряд (после первой неудачи проверки чаще, ~20 с), «ожил» — после 2
удач. При отказе соединения через этот выход сбрасываются, и следующий пакет
выбирает живой. Ушедшие напрямую, пока все выходы лежали, сбрасываются, когда
выход ожил.

### Список российских сетей

`ru-update`: делегирование RIPE (Россия только у RIPE) с проверкой md5, запасной
источник — ipdeny. Меньше 2000 записей — список битый, прежний остаётся.
Таймер `awg-cascade-ru.timer` — раз в сутки. Сети, которые надо гнать через
выход несмотря на список, — в `/etc/amnezia/amneziawg/cascade/force_exit.list`.

DNS устройств (1.1.1.1) не российский и идёт через выход, поэтому Google и
YouTube отвечают зарубежными адресами, а не кэшами в российских сетях.

### Туннель «вход ↔ выход»

- Своя обфускация (генерирует выход, вход берёт из токена): смена параметров
  клиентов туннели не трогает, и наоборот. AWG 3.1, если `awg0` на 3.1, иначе 2.0.
- Свой порт выхода, открыт только для адресов входов (`cascade_entries`).
- MTU 1420, `Table = 2000+K` — маршрут по умолчанию через туннель лежит в своей
  таблице, основная таблица входа не меняется; собственный трафик входа (SSH
  бота, apt) идёт как обычно.
- Адреса: `10.249.K.1` — выход K, `10.249.K.(1+E)` — вход E.

## Порядок установки

На всех серверах: `/root/cascade.sh` (ставится `setup.sh`, или
`curl -fsSL https://raw.githubusercontent.com/yntoolsmail-prog/Vpn_AWG/experimental/cascade.sh -o /root/cascade.sh`).

1. **Вход** — российский ВПС: `setup.sh --slave`, затем добавить в боте как
   обычный сервер (копия основного).
2. **Выход** (на каждом): `bash /root/cascade.sh exit-up --slot K` → токен выхода.
3. **Вход**: `bash /root/cascade.sh entry-add 'ТОКЕН_ВЫХОДА'` → токен входа.
   Второй вход — `--entry 2`. Порядок в «Авто» — `--auto N`, не участвовать — `--no-auto`.
4. **Выход**: `bash /root/cascade.sh exit-peer 'ТОКЕН_ВХОДА'`.
5. **Вход**: `bash /root/cascade.sh status`.

Токены содержат ключ защиты заголовков туннеля — передавать только между своими серверами.

Конфиг устройства через вход: из бота, выбрав сервер-вход (это «Авто»), или на
основном — `bash /root/cascade.sh client-conf УСТРОЙСТВО АДРЕС_ВХОДА [K] [--qr]`.

Снять всё: `bash /root/cascade.sh down` на каждом сервере (`awg0` и устройства не трогаются).

## Файлы

| Путь | Где | Что |
|---|---|---|
| `/etc/amnezia/amneziawg/awgx0.conf` | выход | интерфейс туннелей входов |
| `/etc/amnezia/amneziawg/awgxK.conf` | вход | туннель к выходу K |
| `/etc/amnezia/amneziawg/cascade/exits/K.env` | вход | слот, порядок в «Авто», номер входа |
| `/etc/amnezia/amneziawg/cascade/slots` | вход | слоты, адреса которых держатся у устройств |
| `/etc/amnezia/amneziawg/cascade/ru.zone` | вход | список российских сетей |
| `/etc/amnezia/amneziawg/cascade/force_exit.list` | вход | сети всегда через выход |
| `/etc/amnezia/amneziawg/cascade/entries.ipset` | выход | адреса входов для фаервола |
| `/run/awg-cascade/health` | вход | состояние выходов для `status` |

## Проверено в песочнице

Сетевые пространства: телефон → вход → два выхода, userspace amneziawg-go.
Авто и слоты по выходам, российское напрямую; отказ и возврат выхода (отказ
замечается за ~13 с при интервале 2 с); оба выхода мертвы → напрямую и возврат;
сброс адресов слотов ботом и перезапуск `awg0`; 20 МБ через каскад целиком;
снятие слота; два входа на одном выходе; AWG 2.0; полное снятие без следов.
Пути systemd и скачивание RIPE в песочнице не проверялись (нет systemd и доступа).
